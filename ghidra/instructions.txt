================================================================
GHIDRA SETUP — MegaMan8Recomp
================================================================

Goal: import the Mega Man 8 (USA) boot executable into Ghidra so
functions, labels and structs can feed ../seeds/, ../symbols.toml and
../annotations/.

Game:    Mega Man 8 (USA)
Serial:  SLUS-00453  (on-disc file SLUS_004.53)
Region:  North America (NTSC-U)
Volume:  MEGAMAN8 (Publisher CAPCOM CO.,LTD.)

----------------------------------------------------------------
CPU / processor
----------------------------------------------------------------
The PlayStation CPU is a MIPS R3000A (LSI CW33300 core):
  - 32-bit, LITTLE-ENDIAN, MIPS I integer ISA
  - No hardware FPU. Coprocessors are COP0 (system control) and
    COP2 (the GTE geometry transform engine). Ghidra's default MIPS
    decoder handles the integer ISA fine; GTE (cop2) ops show up as
    coprocessor instructions — that is expected, not an error.

  Ghidra language:  MIPS:LE:32:default
  Compiler spec:    default
  Endianness:       little
  Address size:     32-bit

----------------------------------------------------------------
What to import
----------------------------------------------------------------
Import the HEADERLESS dump (the 2048-byte PS-EXE header is already
stripped, so file offset 0 maps cleanly to the load address):

  ghidra/SLUS_004.53_no_header.bin        (1,126,400 bytes)

(Alternatively import the header-ful boot EXE disc/SLUS_004.53 and set
 the import "File Offset" to 0x800. The headerless dump is simpler and
 is what these notes assume.)

----------------------------------------------------------------
Load / memory layout (read from the PS-EXE header)
----------------------------------------------------------------
  Load address (base):  0x800C0000   <-- file offset 0 maps here
  Entry point (pc0):    0x800C0B3C
  Initial $gp:          not preset (header gp0 = 0). Mega Man 8 sets
                        $gp at runtime; if the MIPS analyzer wants a
                        gp value, derive it from the lui/addiu $gp
                        setup in the entry code at 0x800C0B3C.
  Text size:            0x00113000    (1,126,400 bytes)
  End of text:          0x801D3000    (load_address + text_size)
  Initial $sp (stack):  0x801FFFF0    (PS-EXE header; SYSTEM.CNF STACK = 801FFF00)

PS1 address space, for context:
  0x80000000-0x801FFFFF  KSEG0  cached; the 2 MB main RAM
  0xA0000000-0xA01FFFFF  KSEG1  uncached mirror of the same RAM
  0xBFC00000             BIOS ROM reset vector
The boot EXE loads contiguously at 0x800C0000 (unusually high — the
region 0x80010000..0x800BFFFF below it is left free for streamed
data). Mega Man 8 streams per-stage code from the disc at runtime
(OVL/DEMO.BIN, OVL/STAGE00.BIN .. OVL/STAGE0D.BIN — loaded into RAM
and executed, the analogue of X4's ARC / X5-X6's ROCK overlays);
those overlays are out of scope for the static EXE import and are
handled by the recompiler's overlay-cache pipeline. To study one in
Ghidra, import the OVL/*.BIN as a second Raw Binary at the load
address the game's loader uses for it (find it from the loader code
that reads the file — do not guess).

----------------------------------------------------------------
Project creation
----------------------------------------------------------------
1. Launch Ghidra. File -> New Project -> Non-Shared Project.
2. Name:     MegaMan8Recomp
   Location: <repo>/ghidra/projects/
   (the projects/ subdir is gitignored — Ghidra writes large,
    machine-specific .gpr/.lock/.rep files there.)

----------------------------------------------------------------
Import steps
----------------------------------------------------------------
1. File -> Import File -> select  ghidra/SLUS_004.53_no_header.bin
2. In the import dialog:
     Format:    Raw Binary
     Language:  click "..." , filter MIPS, pick  MIPS:LE:32:default
     Options... -> Base Address:  0x800C0000
3. OK. Accept the auto-analysis defaults, and additionally ENABLE:
     - "MIPS Constant Reference Analyzer"  (resolves lui/addiu and
       $gp-relative address pairs — important on MIPS).
4. Go to the entry point:  G -> 0x800C0B3C , then Disassemble /
   Create Function if it is not already a function. That address is
   the recompiler's entry_pc.

----------------------------------------------------------------
Feeding results back into the project
----------------------------------------------------------------
- Function starts you want the recompiler to seed: add their
  addresses (one 0x-prefixed hex per line) to
  ../seeds/ghidra_funcs.txt   (probe_disc.py pre-filled it with the
  entry + every direct JAL target in the boot EXE — 787 entries; the
  recompiler ALSO discovers functions itself, so seeds are only needed
  for entries the walker cannot reach: indirect / table / overlay
  targets).
- Named functions: add [[func]] rows to ../symbols.toml and run
  python3 tools/sync_symbols.py  to refresh ../psx_symbols.h
  (see psxrecomp/docs/SYMBOLS.md).
- Notes on what a function does: add an  "0xADDRESS, note"  row to
  ../annotations/SLUS_004.53_annotations.csv (hand-curated evidence,
  same convention as MegaManX4Recomp).

----------------------------------------------------------------
Ghidra MCP server (optional, for Claude)
----------------------------------------------------------------
Run the GhidrAssistMCP plugin inside Ghidra
(Window -> GhidrAssistMCP) on its SSE port, then copy
.mcp.json.example -> .mcp.json (server name "psx_ghidra",
http://localhost:8093/sse — 8093 so it can run beside X4's 8092).

----------------------------------------------------------------
Regenerating the headerless dump
----------------------------------------------------------------
If the dump is missing, recreate it from the boot EXE:
  python3 - <<'PY'
  b = open("disc/SLUS_004.53", "rb").read()
  open("ghidra/SLUS_004.53_no_header.bin", "wb").write(b[2048:])
  PY
(disc/SLUS_004.53 itself is re-extracted from the cue by
 psxrecomp/tools/new_project_layout/probe_disc.py --write-boot-exe disc
 or by psxrecomp_cli.py generate.)
